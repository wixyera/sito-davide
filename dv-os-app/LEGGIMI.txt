DV / SPACE 3 — PRIMA DI INIZIARE
==============================

Ciao Davide! Questa cartella contiene il sito aggiornato e tutte le funzioni originali.
Il codice è stato corretto e verificato localmente. La configurazione online di
Supabase, Cloudflare, Spotify e OpenAI va completata nel tuo account: non è stata
eseguita da qui e non sono stati modificati i tuoi dati remoti.

1. AGGIORNARE IL SITO SU GITHUB / CLOUDFLARE

- Conserva una copia della versione attuale.
- Estrai tutto lo ZIP.
- Carica nel repository GitHub il CONTENUTO di questa cartella: index.html,
  package.json, js, css, assets, experiments, functions, vendor e gli altri file.
- Puoi conservare la struttura del repository originale: la cartella di lavoro
  del progetto è dv-os-app. Non aggiungere un ulteriore livello di cartelle.
- Su Cloudflare apri Workers & Pages, scegli il progetto Pages esistente e
  controlla le impostazioni di build:

    Framework preset: None
    Build command: npm run build
    Build output directory: dist
    Root directory: dv-os-app se il sito è ancora dentro dv-os-app;
                    vuota se hai messo package.json nella radice del repository.

- Avvia una nuova distribuzione dopo il caricamento dei file.
- Usa l'URL gratuito pages.dev già assegnato al progetto. Non serve modificare
  il dominio che utilizzi per un altro sito.
- La cartella functions deve stare accanto a package.json. Non caricare soltanto
  dist tramite trascinamento nel pannello Cloudflare: quel metodo non pubblica
  le Pages Functions di questo progetto. Usa GitHub oppure Wrangler.

Alternativa con Wrangler, dalla cartella che contiene package.json:

    npm run build
    npx wrangler pages deploy dist --project-name NOME_DEL_TUO_PROGETTO

Il nome è quello reale del tuo progetto Pages. Non incollare il testo segnaposto.

2. COMPLETARE SUPABASE

- Apri il progetto Supabase che già usi con questo sito.
- La configurazione pubblica esistente è mantenuta in js/config.js.
- Se il progetto è sospeso, riattivalo dal pannello.
- Apri SQL Editor, crea una nuova query e incolla sql/SETUP_COMPLETO.sql.
- Eseguila: crea/completa events, career_entries, contacts, wishlist_items,
  expenses e abilita l'accesso alle sole righe del proprietario.
- Lo script non cancella dati. Eventuali vecchie righe senza user_id restano
  invisibili: non assegna automaticamente dati di proprietà sconosciuta.
- Se le tabelle esistenti hanno colonne obbligatorie aggiuntive o tipi diversi
  da quelli previsti dal sito, serve allineare quello schema specifico.
- Non sostituire la chiave pubblica nel frontend con una secret/service-role key.

3. LOGIN, REGISTRAZIONE E RECUPERO PASSWORD VIA EMAIL

- In Supabase apri Authentication > URL Configuration.
- Imposta Site URL all'indirizzo reale del sito, per esempio il tuo URL pages.dev.
- Aggiungi in Redirect URLs l'URL esatto usato per aprire la home, con slash finale;
  aggiungi anche l'indirizzo che termina in /index.html se utilizzi quello.
- Per provare in locale aggiungi http://127.0.0.1:4173/.
- In Authentication configura il servizio SMTP per l'invio di email.
- I template di conferma e recupero devono includere il collegamento
  {{ .ConfirmationURL }}, per esempio dentro href di un link HTML.
- Se la conferma email è attiva, dopo la registrazione salva il codice di recupero,
  conferma l'indirizzo dalla mail e poi accedi.
- Il nuovo recupero via email si trova in Password dimenticata? > Invia link via email.
- Aprendo il link compare il modulo per scegliere e confermare una nuova password.
- Il vecchio account continua a funzionare: non devi registrarne uno nuovo.

4. RECUPERO CON CODICE PERSONALE

Questo metodo è conservato e richiede la funzione Supabase password-reset.

Metodo dal pannello:
- Apri Edge Functions e crea o modifica password-reset.
- Usa il contenuto di supabase/functions/password-reset/index.ts.
- Per questa sola funzione disattiva la verifica JWT del gateway: viene chiamata
  quando l'utente non riesce ad accedere. La verifica di autorizzazione avviene
  dentro la funzione, confrontando l'hash del codice casuale personale.
- Non togliere la verifica del codice dal sorgente.

Alternativa CLI, dalla cartella del sito:

    supabase login
    supabase link --project-ref ggysihcemzsoqxyzkfnh
    supabase functions deploy password-reset

Il progetto indicato è quello della configurazione originale. Se utilizzi un
altro progetto, cambia sia il riferimento CLI sia URL/chiave pubblica del sito.
La cartella supabase/config.toml contiene già verify_jwt = false per questa
sola funzione. La funzione usa SUPABASE_URL e SUPABASE_SERVICE_ROLE_KEY disponibili
nell'ambiente Supabase; non vanno mai messe nei file pubblici.

Il codice di recupero funziona solo per account che ne hanno effettivamente
registrato l'hash. Per account precedenti o codice perso usa il recupero via email.
La cartella supabase-edge-functions conserva una copia compatibile per chi
utilizzava la vecchia struttura; per nuovi deploy usa la cartella supabase.

5. SPOTIFY, ORACOLO E LINK PRODOTTI

In Cloudflare Pages > Settings > Variables and Secrets, per Production imposta:

    OPENAI_API_KEY            per l'Oracolo IA
    SPOTIFY_CLIENT_ID         per la ricerca Spotify
    SPOTIFY_CLIENT_SECRET     per la ricerca Spotify

Usa valori reali dei tuoi account. Dopo le modifiche ridistribuisci il progetto.
Non inviare chiavi private in chat e non metterle su GitHub.

- Le playlist e i link Spotify si aprono anche senza le credenziali di ricerca.
  La riproduzione dipende da Spotify, dall'account e dal browser.
- L'Oracolo necessita di una chiave API OpenAI abilitata e di credito API.
- L'analisi dei prodotti usa /api/fetch-product e non richiede una chiave aggiuntiva.
  Alcuni negozi ne bloccano la lettura: puoi comunque salvare il prodotto a mano.
- Meteo, Serie A, mappe, ricerca Wikipedia e alcuni esperimenti 3D usano servizi
  esterni. Non funzionano senza rete e la loro disponibilità dipende dai fornitori.

6. PROVA FINALE SUL TUO SITO

- Accedi con il tuo account.
- Crea un evento, modificalo ed esportalo; prova a reimportare un file di esempio
  facendo attenzione a non duplicare gli eventi che vuoi conservare.
- Aggiungi e poi elimina un contatto di prova, una voce di percorso, un prodotto
  in wishlist e una piccola spesa di prova.
- Avvia Focus, mettilo in pausa e riprendilo.
- Apri Galleria 3D; prova stanze, trascinamento e pausa. Se WebGL è bloccato la
  galleria principale passa alla visualizzazione alternativa.
- Prova registrazione, conferma email e recupero con un account di test.
- Controlla Oracolo e ricerca Spotify dopo aver configurato le rispettive chiavi.

7. SE VEDI ANCORA LA VECCHIA GRAFICA

- Prima attendi che Cloudflare indichi il completamento del deploy.
- Chiudi e riapri il sito. Su Windows prova Ctrl+F5.
- Se serve, apri il sito in una finestra privata per distinguere un problema di
  cache da un problema del deploy. Non cancellare i dati del browser per prima cosa.

8. AVVIO DAL PC

Installa Node.js 22 o superiore. Apri il terminale nella cartella del sito:

    npm run dev

Poi apri http://127.0.0.1:4173.
Il doppio clic su index.html non avvia le funzioni del server.
Per controllare il codice: npm test. Per rigenerare dist: npm run build.
